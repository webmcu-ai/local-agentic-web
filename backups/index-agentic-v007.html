File variables: write ${input}, ${filename}, or ${iteration} anywhere in the prompt above to reference the file currently being processed. Any other ${name} is looked up against the other files sitting in the folder right now, matched by the variable name shown in the File Browser panel below — e.g. ${sensor1} pulls in the live content of sensor1.in.txt. This substitution happens in JavaScript before anything is sent to the model, so a prompt like Combine ${sensor1} and ${sensor2}, then explain: ${input} works even though the model itself never sees the placeholder syntax. If a referenced file is missing, it's marked [MISSING FILE VARIABLE: ...] instead of silently disappearing.

Convention (flat filenames, nothing auto-deleted): drop somename.in.txt files into the selected folder. Each pass finds *.in.txt files, resolves the template, and streams the reply live into the terminal above just like a manual Stream click. Clean model output overwrites somename.out.txt every pass; a running commentary log (prompt template, variables resolved, iteration count, chain status) is appended to somename.done.txt. If auto-chain is on and under the iteration cap, somename.in.txt itself is overwritten with the new output so the next pass keeps refining it — same filename throughout, nothing new created, nothing deleted. Once the cap is reached (or auto-chain is off), somename.in.txt is left untouched; use Delete in the File Browser below when you're done with a thread.
